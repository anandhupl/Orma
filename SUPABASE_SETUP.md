# Supabase Database Configuration

This document outlines the required PostgreSQL schema and RPC (Remote Procedure Call) functions necessary to support the Orma RAG pipeline. 

Orma utilizes Supabase's `pgvector` extension to store and query the 768-dimensional embeddings generated by Gemini.

## 1. Enable pgvector Extension
Before creating any tables, you must enable the vector extension in your Supabase SQL Editor.

```sql
create extension if not exists vector;
```

## 2. Table Creation
Create the primary table to hold the chunked textbook corpora.

```sql
create table textbook_corpora (
  id bigint primary key generated always as identity,
  content text not null,
  metadata jsonb not null, -- Stores page numbers (e.g., {"page": "45"})
  subject text not null, -- e.g., "Physics", "Chemistry"
  language text not null, -- "eng" or "mal"
  embedding vector(768) not null -- Gemini Embedding 2 Preview outputs 768 dimensions
);

-- Create an index to speed up vector similarity search
create index on textbook_corpora using hnsw (embedding vector_cosine_ops);
```

## 3. The `hybrid_search_v2` RPC
The `api.py` backend bypasses standard SDKs to execute raw REST calls to this specific RPC. You must execute this SQL to create the function. 

This function performs a cosine similarity search while strictly filtering by the exact textbook subject and language.

```sql
create or replace function hybrid_search_v2 (
  query_text text,
  query_embedding vector(768),
  match_count int,
  subject_filter text,
  language_filter text
) returns table (
  id bigint,
  content text,
  metadata jsonb,
  similarity float
)
language plpgsql
as $$
begin
  return query
  select
    textbook_corpora.id,
    textbook_corpora.content,
    textbook_corpora.metadata,
    1 - (textbook_corpora.embedding <=> query_embedding) as similarity
  from textbook_corpora
  where 
    textbook_corpora.subject = subject_filter 
    and textbook_corpora.language = language_filter
  order by textbook_corpora.embedding <=> query_embedding
  limit match_count;
end;
$$;
```

## Security Note
Ensure Row Level Security (RLS) is configured appropriately if you are exposing the Anon key. Given the current `api.py` implementation uses the Service Role Key (`SUPABASE_KEY`) server-side, standard RLS policies can be set to restrict all public access.
